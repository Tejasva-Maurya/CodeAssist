# MANDATORY: DOCUMENT LIFECYCLE RULES
The following rules dictate how you MUST manage, save, cache, and modify documents generated by this skill. 

## 1. The Registry (Caching)
All CodeAssist documents are tracked in a central JSON registry located at `.codeassist/docs/registry.json` inside the user's workspace.
*   **Step 1:** Before generating any new document, check if `.codeassist/docs/registry.json` exists.
*   **Step 2:** If it exists, read it. If you find a document matching the requested scope and type, you MUST NOT generate a new document. Instead, read the existing `.md` file using your file tools and present it to the user, unless they explicitly ask for a regeneration.

## 2. Iterative Modification
If the user asks to modify or elaborate on a specific section of an existing document (e.g., "Add more detail to the payment flow in 002"):
*   Locate the file path using `registry.json`.
*   Read the file, and use your file-editing tools (`replace_file_content` / `multi_replace_file_content`) to surgically update ONLY the requested section. Do NOT regenerate the entire document from scratch.

## 3. Saving & Versioning (New Documents)
When you generate a brand new document, you MUST save it to the file system. Do not just print it into the chat interface.

*   **Standard Naming Convention:** Save to `.codeassist/docs/[ID]-[ProjectName]-[Scope]-[Type].md`.
    *   *ID:* A sequential 3-digit number (e.g., `001`, `002`). Read the registry to determine the next available ID.
    *   *Scope:* e.g., `Root`, `OrderingAPI`, `Frontend`.
    *   *Type:* e.g., `Architecture`, `BRS`, `FeatureList`.
*   **Agile Naming Convention:** If generating Agile documents (Epics, Stories, Tasks), group them in a subfolder based on the Epic ID: `.codeassist/docs/Agile/[Epic-ID]/[Document].md`.

## 4. Registry Update
Immediately after saving a new document to the file system, you MUST append a new entry to `.codeassist/docs/registry.json`. 
*   **Schema:** `{"id": "001", "project": "eShop", "scope": "Root", "type": "Architecture", "description": "High level context diagram", "file_path": ".codeassist/docs/001-eShop-Root-Architecture.md"}`
*   If the file does not exist, create it with a JSON array `[]`.

## 5. Diagram Formatting (Mermaid Guardrails)
When generating Architecture, Flowchart, or any Mermaid diagrams:
*   **ALWAYS Quote Node Labels:** You MUST enclose node labels in double quotes if they contain commas, parentheses, brackets, or other special characters. 
    *   *Correct:* `id["Label (Extra Info), Text"]`
    *   *Incorrect:* `id[Label (Extra Info), Text]`
*   This is a strict requirement to prevent catastrophic Markdown parsing errors when the user views the document.
